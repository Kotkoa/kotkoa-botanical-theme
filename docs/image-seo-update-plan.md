# План SEO-обновления изображений Shopify

## Цель

Оптимизировать существующие изображения `shop.kotkoa.com` для товарных страниц, Google Images и Pinterest без изменения визуального контента магазина и без загрузки новых файлов.

## Зафиксированные ограничения

- Используются только изображения, уже загруженные в Shopify.
- Главное изображение остаётся текущим.
- Размеры и пропорции исходников не меняются.
- JPEG не перекодируются на первом этапе, чтобы исключить потерю резкости.
- EXIF и ICC-профили не удаляются автоматически.
- Новые изображения и staged uploads не используются.
- Основная задача очистки — удалить визуально одинаковые Printify mockup, созданные отдельно для разных размеров.
- Alt-тексты и новые имена файлов сначала утверждаются в Markdown/CSV-аудите.
- Пилот выполняется только для товара Lavender pillow cover.

## Почему экспорт и обратное обновление должны быть надёжными

Обновление выполняется не по filename, а по стабильным Shopify ID товара, медиа и варианта. Перед изменениями сохраняется полный снимок связей:

- product ID;
- media ID;
- variant ID;
- порядок изображений;
- filename и URL;
- alt text;
- связи изображения с вариантами.

При корректной Admin API-выгрузке обратное обновление воспроизводимо. Дополнительная проверка нужна только потому, что удаление дубликата может очистить variant-media связь. Поэтому перед удалением размерных копий одно сохранённое изображение связывается со всеми соответствующими вариантами.

## Этап 1. Read-only аудит

Скрипт выгружает из Shopify Admin GraphQL:

1. Товары и варианты.
2. Все Product.media с настоящими GraphQL Media ID.
3. Alt, filename, URL, размеры и порядок.
4. Связи media с вариантами.
5. Изображения коллекций.

Результаты:

- `audits/image-seo/<product-handle>.md` — визуальная смета;
- `audits/image-seo/<product-handle>.csv` — машинный план;
- `audits/image-seo/backups/<product-handle>.json` — rollback-снимок.

## Этап 2. Поиск Printify-дубликатов

Проверка выполняется в два уровня:

1. SHA-256 — полностью одинаковые файлы.
2. Перцептивное сравнение — визуально одинаковый mockup для разных размеров, даже если пиксели или форма подушки немного отличаются.

Дубликаты группируются по сцене:

- основной вид спереди;
- front/back mockup;
- обратная сторона;
- front/back обратной стороны;
- zipper/detail.

В каждой группе сохраняется одна текущая картинка. Остальные отмечаются `delete`, но удаляются только после утверждения аудита.

## Этап 3. Alt и filename

Шаблон filename:

`{product-keyword}-{view-or-context}.{original-extension}`

Примеры:

- `provence-lavender-pillow-cover-mediterranean-interior.png`
- `provence-lavender-pillow-cover-floral-front.jpg`
- `provence-lavender-pillow-cover-zipper-detail.jpg`

Расширение не меняется. Alt описывает конкретный кадр естественным английским языком, без повторения одного ключевого запроса во всех строках.

## Этап 4. Dry-run

До записи скрипт показывает:

- какие media остаются;
- какие filename и alt изменятся;
- какие variant-media связи будут добавлены;
- какие дубликаты будут удалены;
- итоговое число изображений до и после.

Запись разрешена только строкам со статусом `approved`.

## Этап 5. Пилот: Lavender pillow cover

Товар:

`provence-lavender-pillow-cover-mediterranean-decor`

Последовательность:

1. Получить настоящие Admin GraphQL Media ID.
2. Сохранить rollback JSON.
3. Связать одно сохранённое главное mockup-изображение со всеми четырьмя вариантами размера.
4. Обновить утверждённые filename и alt через `fileUpdate`.
5. Убрать утверждённые дубликаты из галереи товара через `fileUpdate.referencesToRemove`. Сами файлы временно оставить в Shopify Files для простого rollback.
6. Повторно выгрузить товар и сравнить состояние с планом.
7. Проверить страницу товара, переключение четырёх размеров, галерею и HTML alt.
8. Удалять отсоединённые файлы окончательно только отдельным этапом после проверки и периода ожидания.

## Этап 6. Масштабирование

После успешного пилота тот же процесс запускается для остальных товаров партиями:

1. Pillow covers.
2. Wrapping paper.
3. Wall art.
4. Table linens и bags.
5. Digital collections.
6. Collection images.

Для каждой партии сохраняется отдельный audit, dry-run и rollback.

## JPEG и метаданные

На пилоте JPEG не оптимизируются повторно. У Lavender pillow cover JPEG уже имеют размер `2048 × 2048`, а проверенный файл весит около `236 KB`, поэтому дополнительная компрессия может дать мало пользы и создать риск мыльности. Shopify CDN самостоятельно формирует responsive-версии и современные форматы для браузеров.

Проверенные файлы содержат только небольшие технические EXIF-поля размеров/цветового пространства и ICC-профиль. GPS, данные камеры и крупные Photoshop previews не обнаружены. ICC-профиль сохраняется, чтобы не менять цвет.

## Доступ к API

Нужно создать приложение `Kotkoa Image SEO` в Shopify Dev Dashboard, выпустить версию с минимальными scopes и установить приложение в принадлежащий организации магазин:

- `read_products`;
- `write_products`;
- `read_files`;
- `write_files`.

В `.env` локально хранятся Client ID и Client Secret. Скрипт использует client credentials grant, автоматически получает Admin API access token на 24 часа и обновляет его при следующем запуске. Client Secret и временный token не коммитятся в Git и не отправляются в чат. Сохранённая авторизация Shopify CLI для theme pull/push для Admin GraphQL не используется.

## Критерии завершения пилота

- Главное изображение не изменилось визуально.
- Четыре размера товара продолжают работать.
- В галерее нет размерных копий одинаковых сцен.
- Все оставшиеся изображения имеют утверждённые filename и alt.
- Нет битых изображений или потерянных variant-media связей.
- Rollback-файл позволяет восстановить исходное состояние.
- Отсоединённые дубликаты остаются в Shopify Files до отдельного подтверждения окончательного удаления.
